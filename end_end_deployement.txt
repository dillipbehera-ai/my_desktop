CI/CD Pipeline for Snowflake with Git + Terraform (Step-by-Step)

🔧 Tech Stack:

Source Control: GitHub (or GitLab/Bitbucket) to track code versions.

Infrastructure-as-Code: Terraform to define Snowflake objects (DBs, roles, etc.).

CI/CD Tool: GitHub Actions to automate deployment.

Editor: Visual Studio Code for local development.

Deployment Tool: SnowSQL (CLI to execute SQL).

Transformation Layer: dbt for data modeling and lineage.

Notification: Slack via webhook.

Target Platform: Snowflake (DEV ➝ QA ➝ PROD environments).

🧪 CI/CD Lifecycle for Deploying Snowflake Objects

✅ Step 1: Git Setup & Project Folder Structure

Developer writes SQL/TF/dbt code in VS Code and commits using:

git add . && git commit -m "initial"
git push origin main

→ This pushes changes to GitHub where automation begins.

✅ Step 2: SQL + dbt Project Layout

sql/
  ├── tables/
  ├── procedures/
  └── views/
dbt/
  ├── models/
  └── dbt_project.yml

→ SQL is for raw DDL; dbt builds curated and semantic layers.

✅ Step 3: Terraform Setup

terraform/main.tf example:

provider "snowflake" {
  account  = var.account
  username = var.username
  password = var.password
}

resource "snowflake_database" "db" {
  name = var.database_name
}

Run:

terraform init && terraform apply

→ Creates infrastructure like databases, schemas, roles.

✅ Step 4: GitHub Actions (.github/workflows/deploy.yml)

name: Deploy to Snowflake
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v2

      - name: Install SnowSQL
        run: |
          wget https://sfc-repo.snowflakecomputing.com/snowsql/bootstrap/snowsql-1.2.24-linux_x86_64.bash
          bash snowsql-1.2.24-linux_x86_64.bash

      - name: Run SQL Deployments
        run: ./snowsql -a ${{ secrets.SNOWFLAKE_ACCOUNT }} -u ${{ secrets.SNOWFLAKE_USER }} -p ${{ secrets.SNOWFLAKE_PASSWORD }} \
          -w COMPUTE_WH -d DEV_DB -s PUBLIC -f sql/tables/create_tables.sql

      - name: Install dbt and run models
        run: |
          pip install dbt-core dbt-snowflake
          dbt deps
          dbt run --profiles-dir dbt/

      - name: Send Slack Notification
        uses: 8398a7/action-slack@v3
        with:
          status: ${{ job.status }}
          fields: repo,commit,message,author
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}

→ Runs SQL, dbt transformations, and sends Slack alerts.

✅ Step 5: Secrets to Configure in GitHub

SNOWFLAKE_ACCOUNT, SNOWFLAKE_USER, SNOWFLAKE_PASSWORD

SLACK_WEBHOOK_URL

✅ Step 6: Multi-Env Git Branching

Use branches:

dev → deploys to DEV_DB

release → deploys to QA_DB

main → deploys to PROD_DB
→ Each branch has its own TF vars and SnowSQL config.

🔄 Dev ➝ QA ➝ Prod Promotion

Code commit in dev triggers DEV deployment

QA merges dev → release → deploys to QA

Release merges release → main → deploys to PROD
→ CI/CD auto-runs based on branch rules.
