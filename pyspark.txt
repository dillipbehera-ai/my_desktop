Architect----✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ 2.7--Hadoop 2.6..

+++++++++++++++++++++++++++
 1. spark-submit my_script.py✅✅✅✅
Launches your PySpark application and submits it to the cluster.

Driver starts and initializes SparkSession and SparkContext.

✅ 2. Driver Program✅✅✅✅
Master node running your PySpark script.

Controls the job execution, creates logical plans, and receives final output.


spark = SparkSession.builder.appName("MyApp").getOrCreate()
✅ 3. SparkSession / Logical Plan✅✅✅✅
Any transformation (filter, select, etc.) builds a logical plan lazily.

No execution happens until an action is triggered.


df = spark.read.csv("data.csv").filter("age > 30")  # logical plan created
✅ 4. DAG Scheduler✅✅✅✅
On action (e.g., collect()), logical plan → optimized plan → physical plan → DAG.

Breaks physical plan into stages based on wide vs narrow transformations.


df.show()  # triggers DAG creation
✅ 5. Stage Creation✅✅✅✅
Stage = set of narrow transformations.

New stage created at each wide transformation (like groupBy, join, distinct).


df.groupBy("dept").count()  # wide → new stage
✅ 6. Job Creation✅✅✅✅✅
Every action (like .collect(), .write(), .count()) = one job.

A job is composed of one or more stages.


df.write.parquet("/output")  # one job with 2+ stages
✅ 7. Cluster Manager (YARN/K8s/Standalone)✅✅✅✅
Allocates executors based on request from the driver.

Handles container lifecycle and failure recovery.

✅ 8. Task Scheduler✅✅✅✅
Splits stages into tasks (one task per partition).

Distributes tasks across executors using TaskSchedulerImpl.

✅ 9. Executors✅✅✅✅
JVMs on worker nodes that execute tasks, read/write data, cache, shuffle.

Run independently and send results to driver.

✅ 10. Shuffle / Exchange✅✅✅✅
On wide transformations, Spark shuffles data → writes to disk → transfers over network.

Expensive → try to minimize via broadcast, partition tuning.

✅ 11. Caching / Persistence✅✅✅✅
cache() and persist() store intermediate results in memory/disk.

Reduces recomputation and lineage depth.


df.cache().count()
✅ 12. Garbage Collection (GC)✅✅✅✅
JVM GC clears unused objects. High GC time = memory issues.

Use spark.executor.memory, spark.memory.fraction, or G1GC.


--conf "spark.executor.extraJavaOptions=-XX:+UseG1GC"
✅ 13. Result Collection✅✅✅
For actions like .collect(), the driver aggregates and retrieves data from executors.

Caution: large datasets can cause OOM in driver.

✅ 14. SparkContext Shutdown✅✅✅✅
After job completes, SparkContext is stopped.

Executors shut down, resources are released.

🔄 Example DAG Breakdown (Simple Pipeline)


df = spark.read.csv("s3://data.csv")        # Input
df2 = df.filter("age > 30")                 # Narrow (same stage)
df3 = df2.groupBy("dept").count()           # Wide (new stage)
df3.write.parquet("s3://output/")           # Action → DAG → Job → Stages → Tasks

🔁 Narrow Transformations------------✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ 
(Data stays in same partition – no shuffle)✅ 

Transformation	Impact---
map()		Executes in-place on each partition (fast, no shuffle).
filter()	Keeps only rows matching condition within each partition.
flatMap()	Similar to map but returns multiple outputs per input (no shuffle).
union()		Combines RDDs/DFs without reshuffling data.
sample()	Samples data within each partition locally.
withColumn()	Adds or updates column using row-wise logic (stays local).
select()	Projects selected columns, no data movement.
limit()	Scans partition-wise until limit is satisfied.

🔁 Wide Transformations-----✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ 
(Requires shuffle – data moves between partitions)

Transformation	Impact
groupBy()	Groups data across partitions, triggers shuffle.
distinct()	Deduplicates across partitions, expensive shuffle.
join()	Combines data from multiple DataFrames across partitions.
repartition()	Reshuffles all data to specified number of partitions.
sortBy()	Sorts records globally, causes full shuffle.
reduceByKey()	Combines values per key after shuffling similar keys.
coalesce()	Reduces number of partitions with partial shuffle.
orderBy()	Like sortBy; performs full shuffle to guarantee order.

Summary:

Narrow: Fast, pipelined, stays local — better performance.

Wide: Triggers shuffle, creates new stage — more expensive.

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
🔁 Narrow vs Wide Transformations and Their Impact✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ 
Type	Examples	Effect
Narrow	map, filter, withColumn	Operates on a single partition; no shuffle
Wide	join, groupBy, distinct	Requires shuffling data across partitions

👉 Narrow transformations------------
Output depends only on input from one partition

Spark pipelines them into the same stage

Fast, no shuffle

df.filter("age > 30").select("name")  # narrow → same stage
👉 Wide transformations--------------
Output depends on multiple partitions

Spark creates a new stage after a shuffle boundary

Slower, requires data exchange

df1.join(df2, "id")  # wide → triggers shuffle → new stage
🎯 Job → Stage → Task Breakdown Example
df = spark.read.csv("data.csv")
df1 = df.filter("age > 30")               # Narrow
df2 = df1.groupBy("country").count()      # Wide (shuffle)
df2.show()                                # Action
Component	What Happens
Job	Created when .show() is called
Stage 1	Includes read + filter (narrow, no shuffle)
Stage 2	Includes groupBy.count (wide, shuffle)
Tasks	Each stage splits into tasks, one per data partition

++++++++++++ How to calculate memory---------✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ 
Example Scenario 1: 10 GB file processing
🔹🧠🧠🧠🧠🧠🧠🧠🧠🧠🧠🧠 Step 1: Estimate Memory per Executor
Start with how much memory 1 executor should handle.

Suppose 1 executor handles 1 GB of data safely (based on transformations, caching, join complexity).

Then:

bash
Copy
Edit
num_executors = ceil(10 GB / 1 GB) = 10 executors
🔸 You could increase this to 2 GB/executor if transformations are simple (e.g., just reading + filtering).
🔸 Reduce it to 512MB/executor for heavy shuffles, wide joins, caching.

🔹🧠🧠🧠🧠🧠🧠🧠 Step 2: Set Executor Memory and Overhead
Suppose you allocate 2 GB RAM per executor, Spark will keep ~7% as overhead.

Formula:

bash
Copy
Edit
executor_memory = 2 GB * (1 - 0.07) = ~1.86 GB usable
Remaining ~140 MB used for shuffle buffers, serialization, GC.

🔸 You can also override explicitly:

bash
Copy
Edit
--conf spark.executor.memoryOverhead=512m
📌 MemoryOverhead is crucial if you do wide transformations like join, groupBy, distinct.

🔹🧠🧠🧠🧠🧠🧠🧠🧠🧠🧠 Step 3: Set Number of Executor Cores
Keep 1-5 tasks per executor to balance parallelism and memory.

Example: Assign 2 cores per executor → each executor can run 2 tasks concurrently.

So for 10 executors:

bash
Copy
Edit
total_cores = 10 * 2 = 20 cores
🔸 Avoid more than 5 cores per executor as tasks may compete for memory and GC will suffer.

🔹🧠🧠🧠🧠🧠🧠🧠🧠🧠🧠 Step 4: Set Shuffle Partitions
Spark default is 200 shuffle partitions. You should tune this based on total cores.

Formula:

bash
Copy
Edit
spark.sql.shuffle.partitions = total_cores * 2 = 40
More partitions = better parallelism but more small files/shuffles.

🔸 For simple aggregations, set = total_cores.
🔸 For skewed or high cardinality joins, increase beyond 2 * cores.

🔹🧠🧠🧠🧠🧠🧠🧠🧠🧠🧠 Step 5: Set Driver Memory
Driver loads schema, job plan, and collects results for .collect() or .take().

If your output is expected to be 500 MB:

bash
Copy
Edit
--driver-memory 2g
If you run .collect() on full 10 GB, you'd need driver memory ~10 GB (not recommended).

🔸 Avoid collect() on huge data — prefer write(), foreachPartition().

🔹 Step 6: Enable Dynamic Allocation (optional)
bash
Copy
Edit
--conf spark.dynamicAllocation.enabled=true
--conf spark.dynamicAllocation.minExecutors=2
--conf spark.dynamicAllocation.maxExecutors=15
--conf spark.shuffle.service.enabled=true
Spark scales executors based on load — useful for mixed workloads.

Good for interactive clusters, but disable for strict resource-bound batch jobs.

cache()✅ ✅ ✅ ✅ 
Stores a DataFrame in memory on first action.

Speeds up repeated reads of intermediate results.

Uses LRU policy; can spill to disk if memory is low.

Best for iterative algorithms or reuse-heavy stages.

df.cache(); df.count()

🔹 persist()✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ 
More flexible than cache; allows custom storage level.

Use for large DataFrames: MEMORY_AND_DISK, DISK_ONLY, etc.

Retains data even after action unlike cache (optional).

Use when caching fails due to memory constraints.

df.persist(StorageLevel.MEMORY_AND_DISK)

🔹 partitioning✅ ✅ ✅ ✅ ✅ ✅ 
Distributes data across Spark tasks for parallel processing.

Affects data movement and performance of wide operations.

Can be user-defined (repartition, coalesce).

Too many small partitions cause overhead; too few reduce parallelism.

df.repartition(10) or df.coalesce(2)

🔹 bucketing✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ 
Hashes column values into a fixed number of buckets.

Optimizes join and aggregation performance.

Unlike partitioning, buckets don’t create separate files but improve Spark plan.

Useful for large lookup tables joined often.

df.write.bucketBy(8, 'id').saveAsTable('bucketed')

✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ Narrow Transformation (10 Lines):✅ ✅ ✅ ✅ ✅ ✅ ✅ 
Data is processed within the same partition.

No data shuffling across the cluster.

Examples: map(), filter(), withColumn(), union()

One-to-one mapping of input to output partitions.

Fast and memory-efficient.

No need to recompute other partitions if one fails.

No new stage is created in the DAG.

Mostly occurs within a single stage.

Ideal for simple column-wise operations.

Easier to optimize and monitor.

Example:

python
Copy
Edit
df.filter(col("age") > 30).select("name")
🔹 ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ Wide Transformation (10 Lines):✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ 
Data is shuffled between partitions or nodes.

Requires network I/O → expensive operation.

Examples: groupByKey(), reduceByKey(), join(), distinct()

One-to-many or many-to-one mapping.

Causes a stage boundary in the DAG.

Spark creates shuffle files and new stages.

Can cause skew if data is uneven.

Requires careful partitioning and tuning.

Failure in one partition may cause recomputation.

Key driver for performance bottlenecks.

Example:


df1.join(df2, "id")
🔧✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅  Job & Stage Creation in Spark (10 Lines):✅ ✅ ✅ ✅ ✅ ✅ 

Spark breaks action (collect(), write(), etc.) into jobs.

A job is made up of stages – separated by wide transformations.

Each stage contains tasks, one per partition.

Stages are either narrow or wide.

Narrow stages = one-to-one execution → no shuffle.

Wide stages = require shuffle → new stage boundary.

DAG Scheduler builds DAG from transformations.

Tasks are submitted to Task Scheduler for execution.

Jobs and stages are visible in Spark UI.

Optimizing transformations minimizes stage count.

distinct – Removes duplicate rows.
df.distinct() — Wide: Needs to compare data across all partitions (shuffle).

df.groupBy('region').count() — Wide: Aggregation requires shuffle.

df.groupBy('region').agg({'sales': 'sum'}) — Wide: Global aggregation needs shuffle.

join – Joins two DataFrames on a key.
df1.join(df2, 'id') — Wide: Matching keys across partitions causes shuffle.

union – Appends rows from another DataFrame.
df1.union(df2) — Wide: Data alignment may require reshuffling.

repartition – Redistributes data into specified partitions.
df.repartition(10) — Wide: Triggers shuffle to redistribute data evenly.

coalesce – Reduces number of partitions.
df.coalesce(2) — Wide: Efficiently merges partitions, small shuffle.

explode – Expands arrays into multiple rows.
df.select(explode(df.items)) — Wide: Expanding requires reshuffling data.

pivot – Converts row values into column headers.
df.groupBy('dept').pivot('year').sum('sales') — Wide: Reshaping requires global shuffle.

sort/orderBy – Sorts rows by column(s).
df.orderBy('score') — Wide: Global sorting triggers shuffle.

limit – Limits the number of returned rows.
df.limit(10) — Narrow: Retrieves rows from first few partitions.

withColumnRenamed – Renames a column.
df.withColumnRenamed('old', 'new') — Narrow: Metadata-only change.

alias – Renames column temporarily.
df.select(df.name.alias('username')) — Narrow: Local and in-memory rename.

sample – Randomly samples rows.
df.sample(False, 0.1) — Narrow: Partition-local operation.

drop – Drops a column from the DataFrame.
df.drop('age') — Narrow: Local metadata change.
unionByName – Merges two DataFrames by column names.
df1.unionByName(df2) — Wide: May shuffle if column order differs.

intersect – Returns common rows between DataFrames.
df1.intersect(df2) — Wide: Requires global comparison.

subtract – Returns rows in df1 not in df2.
df1.subtract(df2) — Wide: Compares across partitions.

cube – Performs multi-level grouping on all combinations.
df.cube('region', 'year').sum() — Wide: Needs reshuffle for each grouping.

rollup – Aggregates data hierarchically.
df.rollup('region', 'year').sum() — Wide: Global partial aggregations.

na.fill() – Replaces nulls with specified values.
df.na.fill(0) — Narrow: Nulls replaced in place.

na.drop() – Drops rows with null values.
df.na.drop() — Narrow: Done per partition.

na.replace() – Replaces specified values.
df.na.replace(['N/A'], ['0']) — Narrow: Local value substitution.

withColumnRenamed() – Renames a single column.
df.withColumnRenamed('old', 'new') — Narrow: Metadata change only.

split() – Splits strings into arrays.
df.withColumn('words', split(df.text, ' ')) — Narrow: String operation in-place.

regexp_replace() – Replaces substrings matching a regex.
df.withColumn('clean', regexp_replace(df.text, '[^a-z]', '')) — Narrow: Per-row transformation.

regexp_extract() – Extracts substrings via regex.
df.withColumn('domain', regexp_extract(df.email, '@(.+)', 1)) — Narrow: Local extraction.

when() – Adds conditional logic to a column.
df.withColumn('grade', when(df.score > 50, 'Pass').otherwise('Fail')) — Narrow: Row-based logic.

isin() – Checks if column value is in a list.
df.filter(df.city.isin('NY', 'LA')) — Narrow: Lookup is local.

isNull() / isNotNull() – Filters null or non-null values.
df.filter(df.age.isNotNull()) — Narrow: Local null filtering.

cast() – Changes column data type.
df.withColumn('age', df.age.cast('int')) — Narrow: Per-row conversion.

dropna() – Drops rows with any nulls.
df.dropna() — Narrow: Filters null rows per partition.

fillna() – Alias for na.fill().
df.fillna(0) — Narrow: In-place fill.

replace() – Alias for na.replace().
df.replace('N/A', 0) — Narrow: Per-row substitution.

selectExpr() – SQL-style column selection.
df.selectExpr('salary * 0.1 as tax') — Narrow: Local expression parsing.

monotonically_increasing_id() – Adds unique ID per row.
df.withColumn('id', monotonically_increasing_id()) — Narrow: Local but not sequential.

lit() – Adds a constant column.
df.withColumn('flag', lit(1)) — Narrow: Adds static value per row.

row_number() – Adds row index per group.
df.withColumn('row', row_number().over(Window.partitionBy('dept'))) — Wide: Requires sort/shuffle.

dense_rank() / rank() – Ranks rows per partition.
df.withColumn('rank', dense_rank().over(Window.partitionBy('dept').orderBy('sales'))) — Wide: Requires global ordering.

lead() / lag() – Accesses next/previous row value.
df.withColumn('prev', lag('score', 1).over(Window.orderBy('date'))) — Wide: Windowing causes shuffle.

over() – Used with window functions to define partitions.
row_number().over(Window.partitionBy('region')) — Wide: Partitioning causes shuffle.

explode_outer() – Similar to explode, but includes nulls.
df.select(explode_outer(df.items)) — Wide: Like explode with more tolerance.

array_contains() – Checks if array has a specific value.
df.filter(array_contains(df.tags, 'urgent')) — Narrow: Per-row array lookup.

concat() – Concatenates columns.
df.withColumn('full_name', concat(df.fname, lit(' '), df.lname)) — Narrow: String function per row.

mapValues() – Applies function to values in key-value RDD.
df.rdd.mapValues(lambda x: x + 1) — Narrow: Local transformation.

from pyspark.sql.functions import current_date, lit, col
from delta.tables import DeltaTable

def apply_scd_type_2(stg_table: str, core_table: str, primary_key: str, business_cols: list):
    """
    Apply SCD Type 2 logic to Delta tables.

    Parameters:
    - stg_table (str): Name of staging/source table (e.g., 'stg.customer')
    - core_table (str): Name of core/target Delta table (e.g., 'core.customer')
    - primary_key (str): Business key column name (e.g., 'customer_id')
    - business_cols (list): List of business columns to track (e.g., ['name', 'address'])
    """

    # Read tables
    df_stg = spark.table(stg_table)
    delta_target = DeltaTable.forName(spark, core_table)

    # 1. Expire old records where data changed
    update_cond = " OR ".join([f"target.{col} <> stg.{col}" for col in business_cols])
    base_cond = f"target.{primary_key} = stg.{primary_key} AND target.is_current = 1"

    delta_target.alias("target").merge(
        df_stg.alias("stg"),
        base_cond
    ).whenMatchedUpdate(
        condition=update_cond,
        set={
            "is_current": lit(0),
            "end_date": current_date()
        }
    ).execute()

    # 2. Insert new versions (changed or new records)
    insert_cols = {
        primary_key: col(f"stg.{primary_key}"),
        "start_date": current_date(),
        "end_date": lit(None).cast("date"),
        "is_current": lit(1),
        "del_flag": col("stg.del_flag")
    }

    for c in business_cols:
        insert_cols[c] = col(f"stg.{c}")

    delta_target.alias("target").merge(
        df_stg.alias("stg"),
        f"target.{primary_key} = stg.{primary_key} AND target.is_current = 1"
    ).whenNotMatchedInsert(
        values=insert_cols
    ).execute()

    # 3. Mark logically deleted records
    delta_target.alias("target").merge(
        df_stg.filter("del_flag = 1").alias("stg"),
        f"target.{primary_key} = stg.{primary_key} AND target.is_current = 1"
    ).whenMatchedUpdate(
        set={
            "is_current": lit(0),
            "end_date": current_date(),
            "del_flag": lit(1)
        }
    ).execute()

    print(f"SCD Type 2 applied from {stg_table} → {core_table}")

from pyspark.sql import SparkSession
from pyspark.sql.functions import col, lit, current_date

spark = SparkSession.builder \
    .appName("SCD Type 2 Load") \
    .enableHiveSupport() \
    .getOrCreate()

# Load existing dim data (active only)
dim_df = spark.table("your_db.dim_table").filter("is_active = 'Y'")

# Load new source data
src_df = spark.read.option("header", True).csv("/path/to/incoming_data.csv")

# Step 1: Identify changed records
changed_df = src_df.alias("src").join(dim_df.alias("dim"), "cust_id") \
    .filter("src.name <> dim.name") \
    .select("src.*")

# Step 2: Expire old records
expired_df = dim_df.alias("dim").join(changed_df.alias("chg"), "cust_id") \
    .selectExpr("dim.cust_id", "dim.name", "dim.start_date", "current_date() as end_date", "'N' as is_active")

# Step 3: Add new records
new_df = changed_df.withColumn("start_date", current_date()) \
    .withColumn("end_date", lit(None).cast("date")) \
    .withColumn("is_active", lit("Y"))

# Step 4: Unchanged records (still active)
unchanged_df = dim_df.join(src_df, "cust_id", "left_anti")

# Step 5: Final SCD2 Union
final_df = unchanged_df.unionByName(expired_df).unionByName(new_df)

# Step 6: Overwrite Hive table (full load or use dynamic partition overwrite)
final_df.write.mode("overwrite").partitionBy("is_active").format("hive").saveAsTable("your_db.dim_table")
