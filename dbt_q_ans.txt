Beginner-Level dbt Interview Questions
What is dbt, and what does it stand for?
Answer: dbt (Data Build Tool) is an open-source tool that enables data analysts and engineers to transform data in data warehouses using SQL. It focuses on the transformation layer of the ELT (Extract, Load, Transform) process, supporting data modeling, testing, and documentation.
How does dbt differ from traditional ETL tools?
Answer: Unlike traditional ETL tools that extract and transform data outside the data warehouse, dbt performs transformations within the warehouse using SQL, making it ideal for ELT workflows. It emphasizes modularity, version control, and testing.
What are the main use cases of dbt?
Answer: dbt is used for:
Data transformation: Writing SQL queries to clean and structure data.
Data modeling: Creating structured datasets for analysis.
Testing: Validating data quality and integrity.
Documentation: Generating data lineage and descriptions.
What is a dbt model?
Answer: A dbt model is a SQL file (typically a SELECT statement) that defines a transformation or table in the data warehouse. It’s stored in the models directory and executed as a view or table.
What is the difference between a source and a model in dbt?
Answer: A source refers to raw, untransformed data loaded into the warehouse from external systems. A model is a transformed dataset created by dbt using SQL queries.
What is the purpose of the dbt run command?
Answer: The dbt run command executes all or specified models in a dbt project, creating tables or views in the data warehouse based on the defined SQL transformations.
What is a dbt project?
Answer: A dbt project is a directory containing all necessary files (models, tests, configurations, etc.) to manage data transformations. It includes a dbt_project.yml file for configuration.
What is the dbt_project.yml file used for?
Answer: The dbt_project.yml file defines project configurations, such as project name, model paths, schema settings, and materializations, to control how dbt operates.
What are materializations in dbt?
Answer: Materializations define how dbt models are stored in the warehouse. Common types include:
Table: Creates a physical table.
View: Creates a virtual view.
Incremental: Processes only new or changed data.
Ephemeral: Temporary, non-persisted model.
How do you install dbt?
Answer: dbt can be installed using pip: pip install dbt-<adapter>, e.g., dbt-snowflake for Snowflake. Then, initialize a project with dbt init.
What is the ref function in dbt?
Answer: The ref function references another dbt model, ensuring proper dependency management and execution order. Example: SELECT * FROM {{ ref('model_name') }}.
What is the source function in dbt?
Answer: The source function references raw data tables in the warehouse, defined in a sources.yml file. Example: SELECT * FROM {{ source('source_name', 'table_name') }}.
What is a seed in dbt?
Answer: A seed is a CSV file containing static or reference data, loaded into the warehouse using the dbt seed command.
What is the purpose of the dbt test command?
Answer: The dbt test command runs tests defined in the project to validate data quality, such as uniqueness or non-null checks.
What are generic tests in dbt?
Answer: Generic tests are predefined tests (e.g., unique, not_null) applied to columns in a schema.yml file to ensure data integrity. Example:
yaml

Copy
models:
  - name: customers
    columns:
      - name: customer_id
        tests:
          - unique
          - not_null


What is a snapshot in dbt?
Answer: A snapshot captures historical changes in mutable data, storing them in a table to track updates over time. It’s useful for auditing.
How does dbt integrate with version control?
Answer: dbt integrates with Git for version control, enabling collaboration, change tracking, and CI/CD pipelines through branches and pull requests.
What is Jinja in dbt?
Answer: Jinja is a templating language used in dbt to add logic (loops, conditionals) to SQL models, making them dynamic and reusable.
What are dbt macros?
Answer: Macros are reusable SQL code snippets written in Jinja, stored in .sql files in the macros directory, used to simplify complex logic.
How do you configure a dbt profile?
Answer: A dbt profile is configured in profiles.yml, specifying connection details for the data warehouse (e.g., Snowflake, BigQuery). Example:
yaml

Copy
my_project:
  target: dev
  outputs:
    dev:
      type: snowflake
      account: <account>
      user: <user>
      password: <password>


Intermediate-Level dbt Interview Questions
How does dbt handle dependencies?
Answer: dbt uses a Directed Acyclic Graph (DAG) to manage dependencies, defined via ref functions, ensuring models are executed in the correct order.
What are dbt hooks?
Answer: Hooks are SQL scripts executed at specific points (pre-hook, post-hook) in the dbt lifecycle, used for tasks like creating indexes or cleaning up data.
How do you write a custom test in dbt?
Answer: Custom tests are written as SQL queries in the tests directory, returning rows that fail the condition. Example:
sql

Copy
-- tests/check_positive_values.sql
SELECT * FROM {{ ref('orders') }} WHERE order_amount < 0
If rows are returned, the test fails.
What is an incremental model, and why use it?
Answer: An incremental model processes only new or changed data, reducing runtime and resource usage. It’s defined with materialized='incremental' and a filter condition.
How do you optimize dbt performance for large datasets?
Answer: Optimization techniques include:
Using incremental models.
Partitioning and clustering tables.
Refactoring complex SQL into smaller models.
Leveraging warehouse-specific optimizations (e.g., Snowflake’s clustering keys).
What is the dbt Cloud Python API used for?
Answer: The dbt Cloud Python API automates tasks like triggering runs, retrieving job statuses, or managing projects programmatically.
How do you handle schema migrations in dbt?
Answer: dbt handles schema migrations using ref and source functions, which track dependencies and allow incremental schema changes without breaking pipelines.
What is the purpose of the dbt compile command?
Answer: The dbt compile command generates executable SQL from models without running them, useful for debugging or reviewing generated queries.
How do you use dbt with Snowflake?
Answer: dbt connects to Snowflake via the dbt-snowflake adapter, configured in profiles.yml. Models are written as SQL, and dbt leverages Snowflake’s compute for transformations.
What are dbt packages?
Answer: dbt packages are reusable modules (e.g., dbt-utils) containing models, macros, or tests, installed via packages.yml to extend functionality.
How do you document models in dbt?
Answer: Documentation is added in schema.yml with descriptions for models and columns. Run dbt docs generate and dbt docs serve to create and view documentation.
What is the dbt semantic layer?
Answer: The dbt semantic layer (available in dbt Cloud) provides a consistent interface for defining metrics and business logic, simplifying data access for downstream tools.
How do you handle data lineage in dbt?
Answer: dbt generates a DAG to visualize data lineage, showing dependencies between models and sources, accessible via dbt docs generate.
What is the dbt seed command used for?
Answer: The dbt seed command loads CSV files (seeds) into the data warehouse as tables, useful for static reference data.
How do you manage multiple environments in dbt?
Answer: Use profiles.yml to define multiple targets (e.g., dev, prod) and switch between them using the --target flag in dbt commands.
What is the difference between dbt Core and dbt Cloud?
Answer: dbt Core is an open-source CLI tool for running transformations locally or on custom infrastructure. dbt Cloud is a hosted platform with a UI, scheduler, and additional features like the semantic layer.
How do you debug a performance issue in a dbt project?
Answer: Steps include:
Check query execution plans in the warehouse.
Use dbt compile to review generated SQL.
Optimize with incremental models or partitioning.
Profile long-running models with dbt run --profile.
What are dbt snapshots used for?
Answer: Snapshots track changes in mutable data over time, storing historical records for auditing or analysis. They’re defined with a snapshot block in SQL.
How do you collaborate with other data engineers using dbt?
Answer: Collaboration is enabled through:
Git for version control and pull requests.
Code reviews for model changes.
Documentation in schema.yml for clarity.
dbt Cloud’s team features for task assignment.
What is the dbt clean command?
Answer: The dbt clean command removes compiled files and artifacts from the target directory, ensuring a fresh project state.
Advanced-Level dbt Interview Questions
How do you implement incremental models with a merge strategy?
Answer: Use materialized='incremental' and define a merge condition in the model. Example:
sql

Copy
{{ config(materialized='incremental', unique_key='order_id') }}
SELECT * FROM {{ ref('source_orders') }}
{% if is_incremental() %}
  WHERE updated_at > (SELECT MAX(updated_at) FROM {{ this }})
{% endif %}
This processes only new or updated rows.
How do you use Python models in dbt?
Answer: Since dbt Core 1.3, Python models are defined in .py files, allowing complex transformations using Python libraries. Example:
python

Copy
def model(dbt, session):
    df = dbt.ref("source_model").to_pandas()
    df['new_column'] = df['column'].apply(lambda x: x * 2)
    return df
Requires a compatible warehouse (e.g., Databricks).
How do you handle complex dependencies in large dbt projects?
Answer: Use modular design (staging, intermediate, mart layers), ref functions for explicit dependencies, and dbt deps to manage package dependencies. Visualize the DAG to troubleshoot.
What are some challenges of using dbt at scale?
Answer: Challenges include:
Performance bottlenecks with large datasets.
Managing complex DAGs.
Ensuring test coverage.
Handling schema drift in sources.
How do you integrate dbt with CI/CD pipelines?
Answer: Use GitHub Actions or similar to:
Run dbt test and dbt run on pull requests.
Deploy to production via dbt run --target prod.
Validate changes with dbt compile before merging.
How do you secure sensitive data in dbt?
Answer: dbt relies on the warehouse’s security (e.g., Snowflake’s TDE). Use environment variables for credentials in profiles.yml and restrict access via role-based permissions.
What is the dbt exposure feature?
Answer: Exposures define downstream use cases (e.g., dashboards, APIs) for dbt models, documented in schema.yml to track impact and dependencies.
How do you handle data quality checks in dbt?
Answer: Use generic tests (unique, not_null), custom SQL tests, and dbt-expectations for advanced checks. Automate tests in CI/CD pipelines.
How do you optimize a dbt model with Jinja?
Answer: Use Jinja to modularize logic, loop over columns, or conditionally include code. Example:
sql

Copy
{% set columns = ['col1', 'col2', 'col3'] %}
SELECT
    {% for col in columns %}
    {{ col }}{% if not loop.last %},{% endif %}
    {% endfor %}
FROM {{ ref('source_table') }}
This reduces repetitive SQL.
How does dbt support data governance?
Answer: dbt supports governance through:
Documentation for transparency.
Tests to ensure data quality.
Version control for auditability.
Lineage visualization to track data flow.

What is the dbt DAG, and how do you troubleshoot circular dependencies?
Answer: The dbt Directed Acyclic Graph (DAG) defines model dependencies via ref. Circular dependencies cause errors. Troubleshoot by:
Running dbt compile to visualize the DAG.
Checking ref usage for unintended loops.
Refactoring models to break cycles, often by creating intermediate models.

What is the on_schema_change configuration in dbt?
Answer: The on_schema_change config in incremental models defines behavior when source schema changes. Options:
ignore: Skip changes.
fail: Fail the run.
sync_all_columns: Add new columns.
append_new_columns: Append new columns without dropping. Example: {{ config(on_schema_change='sync_all_columns') }}.

What is the dbt Semantic Layer, and how does it integrate with BigQuery?
Answer: The dbt Semantic Layer, part of dbt Cloud, centralizes metric definitions using MetricFlow, enabling consistent metrics across BI tools. It integrates with BigQuery by generating optimized SQL queries for metrics, leveraging BigQuery’s compute power for fast execution.
How does MetricFlow enhance the dbt Semantic Layer in BigQuery?
Answer: MetricFlow generates dynamic SQL for complex metric calculations, supports joins across models, and optimizes queries for BigQuery’s columnar storage, reducing compute costs and improving performance.
How do you define a metric in the dbt Semantic Layer for BigQuery?
Answer: Metrics are defined in schema.yml using MetricFlow. Example:
schema.yml
yaml
Show inline
This metric is queried via BigQuery’s SQL engine.

How does the dbt Semantic Layer ensure consistency in BigQuery?
Answer: It centralizes metric definitions, preventing duplicate logic across BI tools. BigQuery executes the generated SQL, ensuring consistent results across platforms like Tableau or Looker.
How do you optimize dbt Semantic Layer queries in BigQuery?
Answer:
Use partitioned and clustered tables in BigQuery.
Define metrics with minimal joins in schema.yml.
Leverage BigQuery’s query cache for repeated metric queries.
Set maximum_bytes_billed in profiles.yml to control costs.
