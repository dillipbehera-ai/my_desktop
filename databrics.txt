Component	Description+++++++++++++++++

Photon Engine	C++-based vectorized execution engine for ultra-fast SQL performance (100x faster than vanilla Spark SQL).
Delta Engine	Extends DBR with caching, indexing, and Delta Lake features for ACID-compliant lakehouse tables.

Unity Catalog	Central governance for schema, metadata, permissions, and lineage across all data assets.

Data read from S3/ADLS in Delta Lake format.

Metadata managed by Unity Catalog / Hive Metastore.

📂 4. What Files Are Created in S3?
S3 Directory Structure:✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅ 
sql
Copy
Edit
s3://your-bucket/delta/employees/
├── part-0000.parquet
├── _delta_log/
│   ├── 00000000000000000000.json        ← Initial snapshot
│   ├── 00000000000000000001.json        ← Any DML updates
│   └── ... check-point.parquet          ← Performance optimization
Parquet files store actual data.

_delta_log/ stores commit history, schema, and transaction logs.

🛠️ 5. How Delta Does DML (Insert, Update, Delete)
🔹 Insert
sql
Copy
Edit
INSERT INTO default.employees VALUES (3, 'Jake')
➡ Adds a new Parquet file, appends new JSON commit log in _delta_log/.

🔹 Update
sql
Copy
Edit
UPDATE default.employees SET name = 'Janet' WHERE id = 2
➡ Writes new Parquet file with updated data, logs old file as removed in _delta_log/.

🔹 Delete
sql
Copy
Edit
DELETE FROM default.employees WHERE id = 1
➡ Marks file segments as removed in _delta_log/, writes new files excluding deleted row.

🧠 6. How Query Works Internally✅ ✅ ✅ ✅ ✅ 
User runs SQL query on default.employees

Databricks reads metadata from Glue

Gets the S3 path → reads _delta_log/ → reconstructs active files

Loads only relevant Parquet files into Spark based on partition/Z-Ordering

Section 2: Delta Lake and ETL----------📂✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅

How does Delta Lake support time travel?---------📂
By maintaining snapshots of data using transaction logs, allowing queries on historical versions using VERSION AS OF or TIMESTAMP AS OF.

How do you merge data in Delta Lake?----------📂
Using the MERGE INTO statement, similar to SQL upserts.

What is schema evolution in Delta Lake?------------📂
Allows new columns to be added automatically when data with different schema is written into a Delta table.

What is Z-Ordering in Delta Lake?--------------📂
A performance optimization technique to colocate related information in storage, improving query performance.

What command is used to vacuum Delta tables?-------------📂
VACUUM delta_table_name RETAIN 168 HOURS

Delta Table vs Delta Live Table (DLT)✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅✅


++++++++++++++++++++++++++++++++++++++++++++++
Feature	Delta Table	Delta Live Table (DLT)
Definition	A storage format (Parquet + transaction log)	A managed streaming/batch pipeline framework using Delta
How It's Created	Using CREATE TABLE or df.write.format("delta")	Using @dlt.table or CREATE LIVE TABLE
Execution	Manual or scheduled with notebooks	Runs in a managed, auto-orchestrated pipeline
Orchestration	You manage job sequencing and dependencies	Built-in dependency graph and ordering
Schema Evolution	Must be handled manually	Built-in with @dlt.expect() and @dlt.apply_changes()
Monitoring	Spark UI or job output	DLT UI with built-in lineage, quality, and run history
Best For	Simple batch loads, external control (e.g. Airflow)	Streaming/batch pipelines with auto-manage, retry, logging

Requirements:
Source (STG) Table: stg.customer

Target (Core/Dim) Table: core.customer

Business Columns: name, address, phone

Tracking Columns:

start_date (when record becomes active)

end_date (when record expires)

is_current (1 = current, 0 = expired)

del_flag (1 = deleted, 0 = active)

from pyspark.sql.functions import current_date, lit, col
from delta.tables import DeltaTable

# Load source and target
df_stg = spark.table("stg.customer")
df_target = DeltaTable.forName(spark, "core.customer")

# Step 1: Mark expired records in target where business key matches but data changed
update_condition = " AND ".join([
    f"target.{col} <> stg.{col}" for col in ["name", "address", "phone"]
])
merge_condition = f"target.customer_id = stg.customer_id AND target.is_current = 1"

df_target.alias("target").merge(
    df_stg.alias("stg"),
    merge_condition
).whenMatchedUpdate(
    condition=update_condition,
    set={
        "is_current": lit(0),
        "end_date": current_date()
    }
).execute()

# Step 2: Insert new or changed records (new version or new keys)
df_target.alias("target").merge(
    df_stg.alias("stg"),
    "target.customer_id = stg.customer_id AND target.is_current = 1"
).whenNotMatchedInsert(
    values={
        "customer_id": col("stg.customer_id"),
        "name": col("stg.name"),
        "address": col("stg.address"),
        "phone": col("stg.phone"),
        "start_date": current_date(),
        "end_date": lit(None).cast("date"),
        "is_current": lit(1),
        "del_flag": col("stg.del_flag")
    }
).execute()

# Step 3: Mark logically deleted records (del_flag = 1 in source)
df_target.alias("target").merge(
    df_stg.filter("del_flag = 1").alias("stg"),
    "target.customer_id = stg.customer_id AND target.is_current = 1"
).whenMatchedUpdate(
    set={
        "is_current": lit(0),
        "end_date": current_date(),
        "del_flag": lit(1)
    }
).execute()

CREATE TABLE core.customer (
  customer_id STRING,
  name STRING,
  address STRING,
  phone STRING,
  start_date DATE,
  end_date DATE,
  is_current INT,
  del_flag INT
) USING DELTA;
🎯 Result
Case	Action Taken
New record	Insert with is_current = 1
Changed data	Expire old + insert new version
Deleted record	Expire current version + set del_flag = 1
