What is a Snowflake Warehouse?✅✅✅✅
A virtual compute resource to execute queries. Warehouses can be scaled independently.
CREATE WAREHOUSE my_wh WITH WAREHOUSE_SIZE = 'XSMALL';
2. How to create and resize a warehouse?✅✅✅✅
You can set size (XS to 6XL) and scale dynamically.
ALTER WAREHOUSE my_wh SET WAREHOUSE_SIZE = 'LARGE';
3. What is auto-suspend and auto-resume?✅✅✅✅
Auto-suspend saves cost when not in use; auto-resume restarts when queried.
Example:


ALTER WAREHOUSE my_wh SET AUTO_SUSPEND = 60;

Snowflake offers these standard compute sizes:

Size	Virtual Warehouses	Memory & CPU (approx.)
XSMALL	1	~1 CPU, ~8 GB RAM
SMALL	2	~2 CPU, ~16 GB RAM
MEDIUM	4	~4 CPU, ~32 GB RAM
LARGE	8	~8 CPU, ~64 GB RAM
XLARGE	16	~16 CPU, ~128 GB RAM
2XLARGE	32	~32 CPU, ~256 GB RAM
3XLARGE	64	~64 CPU, ~512 GB RAM
4XLARGE	128	~128 CPU, ~1 TB RAM
5XLARGE	256	~256 CPU, ~2 TB RAM
6XLARGE	512	~512 CPU, ~4 TB RAM

📊 For Managing 20 TB of Data in Production
✅ Recommendations depend on query complexity, concurrency, and latency SLAs:

🔹 Basic ETL / Reporting Workloads:
MEDIUM or LARGE may be sufficient.

Use auto-scaling (multi-cluster) for concurrency.

🔹 Heavy Joins / Complex Analytics / BI Tools:
Start with XLARGE or 2XLARGE

Enable multi-cluster (up to 3-5) for high concurrency.

🔹 High Throughput + Real-Time Pipelines:
Use 3XLARGE or above (especially for Snowpipe, streams, materialized views).

🛠 Example Setup for Production:
CREATE WAREHOUSE prod_etl_wh
  WAREHOUSE_SIZE = '2XLARGE'
  MAX_CLUSTER_COUNT = 3
  AUTO_SUSPEND = 300
  AUTO_RESUME = TRUE
  INITIALLY_SUSPENDED = TRUE;
✅ Monitor and adjust using:✅✅✅✅✅

SELECT * FROM SNOWFLAKE.ACCOUNT_USAGE.WAREHOUSE_LOAD_HISTORY;
